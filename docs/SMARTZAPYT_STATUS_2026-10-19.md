# SmartZapyt: состояние проекта и безопасная передача работы

Срез: **19 октября 2026 года**. Репозиторий: [Sereban-glitch/info-bot-go](https://github.com/Sereban-glitch/info-bot-go). Это исходная точка для следующего исполнителя, а не свидетельство нового развёртывания. Перед работой сверить актуальные HEAD, PR, Actions и Releases.

## 1. Решение владельца и границы

- **Саша — оркестратор; Z.ai — основной исследователь и разработчик следующего этапа.** Сначала исследование **топовых юридических продуктов**: пройти доступные публичные сценарии, нажимать реальные кнопки и разобрать «вход → уточнения → результат → следующий шаг», затем независимо воспроизвести полезные решения. Готовые open-source модули/API — вторичный способ реализации, не главная цель. Далее варианты MVP и реализация после существенного выбора владельца.
- Рабочий Telegram-бот сохраняем. Компактный синий интерфейс TideGuide уже одобрен и установлен в веб-версии. Он остаётся основой; повторный полный редизайн не нужен.
- Нравится направление названия **Smart**; часть **Zap** не устраивает. Новое имя не выбрано. Не переименовывать продукт, package ID, домены или бота самовольно.
- Узкие исправления интерфейса и выпуск Android уже ведутся отдельно. Не запускать второго автора тех же файлов. Новые модули, восстановление старых экранов и монетизацию не подмешивать к ремонту.
- Заявленные ограничения: существующая VM с **1 ГБ RAM** и текущая AI-инфраструктура. Это бюджет проектирования, а не проведённый нагрузочный замер. Пользовательский результат должен быть **бесплатным в пределах реального бюджета/квот**, с честным запасным сценарием; не обещать безлимит и не вводить платные уровни самовольно.
- Обязательны украинские сервисы, включая понравившийся владельцу UX e_Advocat_bot. Пока проверены только публичные представления, не внутренние диалоги. Судебный реестр/мониторинг — отдельный кандидат для изучения разрешённого доступа, не уже обещанный модуль.

## 3. Где настоящая реализация

- Go **1.24.1+**, Telebot v3; код бота — `internal/bot/handlers`; API/авторизация — `internal/web`; интеграция портала — `internal/dostup`; файловые пользовательские данные — `internal/session`, `internal/sentlog`, `internal/stats`.
- Go встраивает и отдаёт **`internal/web/static`**. Именно HTML и assets здесь определяют работающий MiniApp.
- Оригинальный React-проект и source maps в доступной истории не восстановлены. `mini-app/patches/` — читаемый восстановленный слой поверх сохранённого bundle, `mini-app/build-patches.mjs` — воспроизводимый fail-closed генератор. Не редактировать только минифицированный результат и не выдавать этот слой за полный исходный React-проект.
- Корневой `mini-app/index.html` — другая legacy-реализация; правка только этого файла не доказывает изменение работающего приложения.
- Android: Capacitor 8, `com.smartzapyt.app`, `mobile/www`; CI копирует туда `internal/web/static`. APK содержит собственные assets и не получает новый UI только от обновления веб-сервера.
- Собственная лицензия проекта — [MIT](https://github.com/Sereban-glitch/info-bot-go/blob/41b9b274f18928bd47873dc434f98c19fcad235d/LICENSE). Лицензии доноров, API и данных проверяются независимо.

## 4. Что уже есть: сначала использовать, потом изобретать

**Текущий MiniApp:** обзор, запросы, рейтинг, аналитика; шесть фильтров запросов; детали конкретного запроса; безопасные ссылки на источник; вход кодом из бота; Telegram initData и сохранённый native login; обновление при возврате в приложение. Кнопки бота открывают общий чат, не отправляют сообщение и не продолжают автоматически выбранный запрос.

**Бот и серверный код:** создание запросов, шаблоны, AI-разбор ответов, голосовой ввод, профиль, мои запросы, follow-up, каталог органов, поиск по публичным запросам, работа с документами/вложениями, статистика и административные функции. Наличие обработчика не доказывает доступность каждого сценария в текущем UI или его production-конфигурацию.

**Есть API-кандидаты для повторного использования:** `/api/templates`, `/api/generate-template`, `/api/analyze`, `/api/bodies`, `/api/search-requests`, POST `/api/requests`, POST `/api/followups`, `/api/events`. Перед возвратом записи/отправки обязательны тесты владения объектом, авторизации, модерации и явного подтверждения отправляемых данных. Не считать API безопасным только по факту наличия `authMiddleware`.

**Историческая потеря функций:** последний обслуживаемый HTML до React имел семь вкладок: обзор, запросы, новый запрос, библиотека, разбор, рейтинг, профиль. В нём были формы, документы, follow-up, поиск/сортировка рейтинга и переключение аккаунта. Основная потеря относится к миграции **`0e1a283` от 12 сентября**, а не PR9. PR8 уже обслуживал четыре направления; PR9 сохранил их и добавил детали/ссылки. Старые формы нельзя просто включить без проверки действующих API и прав доступа.

## 5. Что делает узкий ремонт, а что не делает

Кандидат `9c987ca` возвращает countdown/срочность/дату отправки карточкам, независимо показывает ближайший незавершённый запрос и последний ответ, различает пустую категорию и пустой аккаунт, исправляет подпись автоответа и выводит уже определённую долю успешных запросов. Ссылки в бот используют Telegram SDK с безопасным обычным переходом как запасным вариантом.

Сохранённый фрагмент ответа показывается буквально и с исходным текстом: реальные CSV-строки можно аккуратно отобразить; сплющенные поля не превращаются в выдуманную таблицу; повреждённый/обрезанный хвост и redaction-placeholder не восстанавливаются догадками. Новые загрузки с портала сохраняют явные переводы строк и обрезаются по Unicode code points, а не посередине UTF-8.

**Не входит:** исправление уже сохранённых финализированных фрагментов, массовая повторная загрузка, восстановление исторических функций, новые AI-модули, перенос данных, изменение подписей Android. Отдельный backfill потребует ограниченного плана, разрешения и защиты от повторных уведомлений/смены статусов.

## 6. AI и экономика: код ≠ production-настройка

[Конфигурация](https://github.com/Sereban-glitch/info-bot-go/blob/41b9b274f18928bd47873dc434f98c19fcad235d/internal/config/config.go) и `internal/ai/` подтверждают прямой клиент **Google Gemini** и настраиваемый proxy. Значения по умолчанию: `gemini-3-flash-preview`, резерв `gemini-2.5-flash-lite`; proxy задаётся через `AI_PROXY_*`, поддерживает Messages/OpenAI-совместимый маршрут, возможен fallback к прямому Gemini. Это **не доказательство** реально выбранной модели, поставщика proxy, квоты, тарифа или доступности этих моделей на дату внедрения. Рабочая формулировка владельца «Google proxy» требует проверки несекретных runtime-параметров, без чтения/публикации ключей.

Каркас Telegram Stars уже есть; `STARS_ENABLED` по умолчанию false, предусмотрены лимиты дорогих операций. Не включать оплату, не менять лимиты и не обещать бесплатный AI без отдельного выбора. Для каждого MVP нужны цена успешного сценария с retries/fallback, месячные сценарии нагрузки и полезный путь без AI при исчерпании бюджета.

## 7. Воспроизводимость и выпуск

Из корня checkout кандидата, Node 22 и совместимый Go:

```sh
node mini-app/build-patches.mjs --check
node --test mini-app/patches/*.test.mjs
for asset in internal/web/static/assets/index-status-*.js; do node --check "$asset"; done
go test ./... -count=1
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o /tmp/info-bot-linux-amd64 .
```

DOM-тесты — изолированно от app dependencies:

```sh
npm install --prefix /tmp/smartzapyt-dom-qa --ignore-scripts --no-audit --no-fund jsdom@30.1.3
SMARTZAPYT_QA_NODE_MODULES=/tmp/smartzapyt-dom-qa/node_modules node mini-app/qa/dom_test.mjs
SMARTZAPYT_QA_NODE_MODULES=/tmp/smartzapyt-dom-qa/node_modules node mini-app/qa/deadline_dom_test.mjs
```

`mini-app/qa/ui_test.py` и job `miniapp-ui` проверяют настоящий compiled UI в Chromium на синтетических данных. Не публиковать пользовательские кейсы, токены, сырые логи или реальные профили в fixtures, скриншотах и отчётах.

**Осторожно с main:** `deploy.yml` запускает сборку, замену бинарника и restart сервиса при каждом push в main, включая docs-only. Этот workflow не ждёт отдельный CI. `build-apk.yml` тоже запускается на main; публикация APK в Releases предусмотрена для `v*`. Не сливать/тегировать ради доставки документа. Сначала review branch, тесты, решение о выпуске.

`release.yml` пока указывает Go 1.21 при `go.mod` 1.24.1: привести toolchain к согласованной версии и проверить до следующего tag-release. Само наличие workflow не доказывает успешный выпуск.

## 8. Android: реальный блокер обновления

Аудит сравнил старый сентябрьский APK и новый синий CI APK: **сертификаты подписи различаются**, оба debug. Постоянная Android signing-конфигурация не подтверждена. В проверенном базовом Gradle всё ещё `versionCode 1`, `versionName "1.0"`; GitHub-тег `v1.1.5` не равен внутренней версии APK. Отдельный локальный commit `3348b4955c1d7120fa66f9bc584f84ee405758a9` уже меняет версию на `2 / 1.1.6` и добавляет проверку bundled UI/native identity/signature metadata: 4 файла, 5 тестов по отчёту аудитора. Он **не опубликован и не включён** в 21-файловый ремонт интерфейса; это не готовый безопасный upgrade.

Согласно [Android signing documentation](https://developer.android.com/studio/publish/app-signing), для обновления поверх установленного приложения нужны подходящий прежний signing key, тот же applicationId и корректный больший versionCode. Создание нового ключа или увеличение номера не устраняет несовпадение подписи. Нужен исходный keystore **либо явное решение владельца о миграции** с объяснением установки/сохранности данных. Не генерировать новый ключ, не менять package ID, не советовать удаление установленного приложения и не выпускать тег как якобы бесшовное обновление без этого решения. Секреты не передавать через GitHub/Z.ai/чат.

## 9. Обязательная приёмка любого следующего изменения

- Все существующие маршруты/фильтры/кнопки; countdown сегодня/завтра/просрочено; независимость deadline и последнего ответа; пустота/ошибка/повторная загрузка.
- Refusal/partial/unrated — отдельные значения; bounce не ответ. Рейтинг — успешные/все, минимум 5; агрегаты портала не смешивать с журналом приложения.
- Подпись и срок Telegram initData, native login, 401, разлогинивание/смена аккаунта, отсутствующий ID и данные двух синтетических пользователей. Отдельно доказать невозможность чужих чтений, follow-up, отправок и удалений.
- UTF-8, escaped HTML, CSV/обрезанные поля, allowlist исходных ссылок; никаких реконструированных адресов или содержания ответа.
- RAM/RSS, пик CPU, размер bundle/APK, latency, сетевые сбои и лимиты AI измерять; тестовые нагрузки не отправляют реальные запросы органам.
- До promotion сохранить SHA/артефакт прошлого релиза и согласовать откат; после него проверить service/HTTP/assets/Telegram. Откат UI — предыдущий проверенный commit и binary/assets; изменения данных требуют собственного обратимого плана. Доступность возврата APK отдельно зависит от подписи и versionCode.
